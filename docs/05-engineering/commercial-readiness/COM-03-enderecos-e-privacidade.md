# COM-03 — Endereços e privacidade

**PROPOSTO PARA RATIFICAÇÃO · 16/10/2026.** Modelo final candidato para revisão, não cadastro implementado. [ADR-012](../../04-architecture/adrs/ADR-012-politicas-cotacao-entrega-enderecos.md) já ratificou separação de Profile, titularidade e revisões; os detalhes abaixo não ganham aprovação por consequência.

## Campos e comparação com CP-01

Base inspecionada: [CP-02 — modelo TEST_ONLY](../customer-profile/CP-02-modelo-e-versionamento.md), nove campos postais. Todos os novos limites e mudanças de opcionalidade são candidatos. O contrato futuro deve ser fechado (`additionalProperties: false`), com objetos de entrada separados dos de saída para evitar mass assignment.

| Campo candidato | Obrigatoriedade, limite e normalização propostos                                                                             | Comparação com os nove campos CP                                                                                       |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| recipient       | Obrigatório, 1–160 caracteres após NFC/trim, não vazio                                                                       | Preserva destinatário e limite técnico                                                                                 |
| postalCode      | Obrigatório, string de oito dígitos, preserva zeros; aceitar na entrada oito dígitos ou formato exato 99999-999 e normalizar | Preserva CEP; formato aceito não comprova existência                                                                   |
| region          | Obrigatório, uma das 27 siglas UF, duas letras maiúsculas                                                                    | CP aceita duas letras, incluindo ZZ artificial; ZZ não seria permitido publicamente                                    |
| city            | Obrigatório, 1–160 caracteres                                                                                                | Preserva município; não sobrescrever silenciosamente com consulta postal                                               |
| district        | String 1–160 ou null quando localidade comprovadamente não o possui                                                          | CP exige texto; flexibilização depende da política postal aprovada, sem inventar bairro Centro                         |
| street          | Obrigatório, 1–160 caracteres                                                                                                | Preserva logradouro; casos rurais precisam de descrição válida e revisão de entregabilidade                            |
| number          | String 1–20 quando withoutNumber=false; null quando true                                                                     | CP aceita texto 1–160; estreitamento é mudança contratual candidata, não migração automática                           |
| complement      | String até 160 ou null; vazio normalizado a null                                                                             | Preserva complemento opcional; não inserir referência sensível desnecessária                                           |
| country         | Obrigatório, literal BR                                                                                                      | Preserva país; sem entrega internacional implícita                                                                     |
| withoutNumber   | Boolean obrigatório; exclusão lógica com number, sem substituir por número zero                                              | Novo; entrada explícita do usuário                                                                                     |
| nickname        | Opcional, null ou 1–40 caracteres; metadado privado, não parte postal                                                        | Novo; não deve integrar snapshot logístico sem finalidade                                                              |
| addressId       | Gerado pelo servidor, opaco de 8–128 caracteres na fronteira HTTP                                                            | Identidade técnica fora dos nove; UUID interno não é autorização nem exigência pública nova                            |
| version         | Inteiro 1–2147483647 na saída; expectedVersion positivo em edição/desativação                                                | Versão técnica CP: criação com expectedVersion=0 internamente. Não expor controle de versão como campo postal editável |
| eligibility     | Saída server-side ELIGIBLE/INELIGIBLE/RETIRED, enum candidato                                                                | Não confiar em eligibility enviado pelo usuário; elegibilidade depende da política, não só preenchimento               |

Preservar acentos e nomes; NFC/trim não remove informação arbitrariamente. Rejeitar controles, entradas só de espaços e limites excedidos; usar parâmetros SQL e codificação contextual na apresentação. Não executar HTML nem aplicar filtros destrutivos para simular segurança. Contar limites de caracteres de forma consistente no validador/DB, com testes Unicode; não truncar dados silenciosamente.

Versões são imutáveis; update cria revisão e exige expectedVersion. RETIRED é terminal no candidato, sem reativação automática por replay. Quotes recebe somente ID/versão, país/CEP e elegibilidade necessários; Orders retém snapshot postal autorizado. Uma alteração posterior não modifica o destino de pedido já preparado. A retenção desse histórico exige a análise abaixo.

## Validação postal

| Alternativa                    | Capacidade e falha segura                                                                                                                                                                           | Decisão                                                                                                     |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Sintaxe local                  | Oito dígitos/UF/campos e relação número/sem número; funciona sem rede. Não comprova CEP existente, titularidade ou entregabilidade.                                                                 | Necessária, insuficiente como validação postal completa                                                     |
| Preenchimento externo auxiliar | Enviar apenas CEP a serviço escolhido/allowlisted, com timeout e limites, fora de locks DB; devolver sugestão para confirmação explícita. Nunca enviar conta/endereço completo por conveniência.    | PROPOSTO; [ViaCEP](https://viacep.com.br/) documenta consulta, mas não foi integrado, contratado ou testado |
| Conferência oficial            | [Correios — consulta de faixas](https://buscacepinter.correios.com.br/app/faixa_cep_uf_localidade/index.php) permite conferência de localidade; consulta documental não certifica entrega a imóvel. | Política e eventual serviço oficial PENDENTES; não automatizar scraping como integração aprovada            |
| Confirmação do cliente         | Usuário revisa destinatário, número/sem número, complemento e sugestões; registrar versão confirmada                                                                                                | Necessária; declaração não prova propriedade do imóvel                                                      |

Fontes públicas consultadas em 16/10/2026. Cache futuro deve ter fonte/data/validade e não tornar dado antigo certeza atual. Falha do serviço auxiliar permite edição manual do cadastro; a elegibilidade física só é concedida se todos os critérios obrigatórios aprovados puderem ser verificados. Se uma verificação externa for obrigatória e estiver indisponível, bloquear cotação física com dependência indisponível, sem afirmar CEP inexistente nem fazer fallback para tarifa arbitrária. Digital não precisa de endereço físico. O responsável deve escolher entre política somente local limitada à DEMO e verificação postal adicional; nenhuma está homologada.

## Operações HTTP candidatas, não criadas

| Operação PROPOSTA                                | Entrada candidata                                                                                       | Sucesso candidato                         | Condições                                                                                      |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------- | ----------------------------------------- | ---------------------------------------------------------------------------------------------- |
| POST /api/v1/me/addresses                        | Campos postais e nickname/withoutNumber; nenhum ownerId, version ou eligibility controlado pelo cliente | 201 AddressView, versão 1                 | Servidor associa à sessão; idempotência por ator/operação                                      |
| PUT /api/v1/me/addresses/{addressId}             | Substituição completa dos campos editáveis + expectedVersion                                            | 200 AddressView, nova revisão             | Sem upsert de ID desconhecido; comparação atômica de versão                                    |
| GET /api/v1/me/addresses                         | Cursor opaco vinculado ao titular, limit 1–50, padrão candidato 20                                      | 200 lista paginada de AddressView próprio | Dados necessários à seleção/edição; no-store, sem listagem global nem detalhe de outro titular |
| POST /api/v1/me/addresses/{addressId}/deactivate | expectedVersion                                                                                         | 200 AddressView RETIRED, nova revisão     | Histórico referenciado preservado conforme retenção; sem apagar snapshot de pedido             |

AddressView contém os campos candidatos acima, sem sessão, dados financeiros ou IDs de outro titular. Paths, DTOs, limites e respostas ainda exigem ratificação; não estão adicionados ao OpenAPI ativo. Não se cria rota de consulta postal ou detalhe extra implicitamente.

Todas exigem cliente autenticado ativo e autorização no servidor; mutações também Origin/CSRF. Proposta de Idempotency-Key nas três mutações: mesmo padrão CT-03 de 16–128 caracteres, escopo ator+operação e fingerprint canônico. Replay retorna revisão resultante da ação original sem reaplicar mudança; consulta da lista obtém estado atual. Chave com outro corpo ou versão divergente → 409. Ausente/estrangeiro → 404 uniforme, sem revelar titular. Mapeamento completo e casos futuros: [COM-04](COM-04-quote-result-e-contratos.md).

## Privacidade e retenção candidatas

Todas as bases legais são **CANDIDATAS SUJEITAS À REVISÃO**, sem parecer jurídico ou conformidade LGPD concluída. Execução de contrato/procedimentos a pedido, obrigação legal e legítimo interesse são hipóteses distintas; consentimento não é base universal. A [LGPD, arts. 7, 15 e 16](https://www.planalto.gov.br/ccivil_03/_ato2015-2018/2018/lei/l13709compilado.htm) e a [orientação ANPD sobre direitos](https://www.gov.br/anpd/pt-br/assuntos/titular-de-dados/direito-dos-titulares), consultadas em 16/10/2026, exigem examinar finalidade e condições de conservação/eliminações. Não se extrai delas um prazo único para a loja.

Fixtures sintéticas descartáveis continuam sendo destruídas ao fim do laboratório; isso não determina a retenção comercial. Dados pessoais reais em Test Mode continuam dados pessoais. Snapshot imutável e direito de eliminação precisam de desenho futuro para separar fatos comerciais, PII e acessos; não editar provas financeiras nem prometer anonimização só porque existe hash.

Antes da ativação: inventário de dados/operadores e transferências, aviso de privacidade, canal de direitos, política de conservação/exceções, ciclo de backup, segregação e testes de exportação/eliminação autorizada. Nenhuma solicitação de exclusão deve liberar replay financeiro. [COM-D02/03](COM-07-decisoes-e-roadmap.md) continuam PENDENTES.
